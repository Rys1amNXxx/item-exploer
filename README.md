# Item Explorer / 物品资源管理器

独立的 Minecraft Forge 存储模组，目标是用文件夹和资源管理器式界面管理游戏物品。
当前发布版本为 **0.4.0**：包含存储终端、目录树、NAS 硬盘、物品搜索、手动工作台、外部物流、基站结构、数据导线接入、终端物品发送、目录程序文件和原版机器自动加工。
项目仍在持续开发，容量、外观和交互可能继续调整。

## 下载与安装

在 [GitHub Release v0.4.0](https://github.com/Rys1amNXxx/item-exploer/releases/tag/v0.4.0) 下载
`itemexplorer-1.20.1-0.4.0.jar`，放入游戏实例或服务器的 `mods/` 目录。
需要 **Minecraft 1.20.1、Forge 47.4.23 或更新的 47.x、64 位 Java 17**；不适用于 Fabric 或其他 Minecraft 版本。
多人游戏的客户端和服务端需安装同一版本。升级前备份存档，并移除 `mods/` 中的旧版 Item Explorer JAR，避免重复加载。
下载页同时提供 SHA-256 校验文件；完整更新内容见 [0.4.0 发布说明](docs/releases/v0.4.0.md)。

## 游戏中使用

合成“物品存储终端”，放置后右键打开。也可在创造模式独立的“物品资源管理器”分页找到，
或在允许命令的世界使用 `/give @s itemexplorer:storage_terminal`。

配方：7 个铁锭、1 个红石粉、1 个箱子。

```text
铁 红石 铁
铁 箱子 铁
铁  铁  铁
```

| 操作 | 方法 |
| --- | --- |
| 存入 | Shift 点击下方背包中的物品，存入当前文件夹 |
| 存入鼠标上的物品 | 点击“存入”，或点击右侧物品区 |
| 新建文件夹 | 进入父文件夹，点击“新建”，选择文件夹类型，输入名字后确定 |
| 浏览子文件夹 | 主区域优先显示当前目录的子文件夹，单击进入；点击上方路径返回祖先目录 |
| 展开 / 折叠目录树 | 点击左侧文件夹前的箭头，点击名称则进入目录 |
| 改名 / 删除 | 进入文件夹后操作；只能删除空文件夹，主存储盘不可删除 |
| 指定数量取出 | 选择条目，输入数量，点击“取出” |
| 快速取出 | 右键条目取 1 个，Shift 点击条目取最多 64 个 |
| 手动合成 | 把背包材料放入左下方 3×3 工作台，点击右侧结果取走产物；终端内的材料需先取出到背包 |
| 连续合成 / 退回材料 | Shift 点击合成结果，将可合成的产物放入背包；Shift 点击材料格，将该格材料退回背包 |
| 指定数量移动 | 选择条目、填写数量，再拖到左侧目录、主区域的文件夹或上方路径，也可点击“移动到…”后选择目标 |
| 移动 / 取出全部 | 选择条目，点击“全部”填入数量，再执行移动或取出 |
| 翻页 / 滚动目录 | 使用上一页、下一页按钮，或在对应区域滚动鼠标滚轮 |
| 搜索 | 点击“搜索”或 Ctrl+F，默认搜索当前盘的所有目录；可切换为当前目录及子目录 |
| 定位搜索结果 | 选择结果点击“定位”，或双击结果，打开来源目录并高亮物品 |

同种物品可以分配到多个目录；分类移动不会增减总库存。
耐久、名称、附魔等数据不同的物品分别存储。取出时遵守原版堆叠上限，
背包放不下的部分继续留在设备中。

工作台使用原版配方和手动合成规则，搜索期间也可操作；不会自动从存储盘扣除材料。
合成格属于每位玩家当前打开的窗口，关闭终端或打开程序窗口时，剩余材料会返还背包；
背包装不下的材料按原版规则掉落。再次打开时合成格为空。

窗口使用接近原版容器的灰色边框和凹槽，保留原版按钮。
根据屏幕可用空间从 320 × 234 扩展到 440 × 340 逻辑像素，每页可显示 6–25 个文件夹或物品。
悬停仅补充物品信息、必要状态与简短快捷键提示；操作方式见上表。成功操作不显示常驻文字，失败提示短暂显示后消失。

终端本地盘的所有目录共享 **4,096 件物品、128 个条目**的容量；同种物品在不同目录分别占一个条目。
最多 64 个目录（含主存储盘）、8 层子目录，名称最长 24 个 UTF-16 代码单元。
单个物品样本序列化数据上限为 8 KiB；终端、NAS 和硬盘不能放入任何存储盘。

**拆除终端会将本地盘库存掉落到世界中，目录结构不会保留在掉落方块上。**
掉落物仍受原版消失、火焰、爆炸等规则影响，搬家前建议先取出物品。
0.3.0 可通过单独的物流接口接入漏斗 / 管道，0.4.0 增加当前盘物品搜索及终端间发送；远端库存浏览、排序、目录重排和玩家权限系统尚未实现。
可以接近设备的玩家都能使用它。

0.1.2 增加存档保护：未知版本、损坏目录或异常物品数据会使终端进入“数据保护中”，
暂停存取并原样保存整份数据；服务端会尝试在世界目录的 `itemexplorer-recovery/`
生成独立的压缩 NBT 恢复文件，日志记录原因、方块位置和文件路径。
恢复文件不会自动导入库存。恢复步骤与多人验收清单见 [P0 稳定性说明](docs/p0-reliability.md)。

## NAS 与硬盘（0.2.0）

将四盘位 NAS 放在终端的正后方（屏幕的相反方向），右键 NAS，
Shift 点击背包硬盘安装，或拿起硬盘后点对应盘位的“安装”。“弹出”需要背包有一个空位。
回到终端，左侧硬盘与主存储盘并列；选择硬盘根节点后点“改名”可自定义盘名。

也可用数据导线连接分开放置的终端与 NAS，双方六面均可接线，无需基站。
终端会显示全部可达 NAS 的硬盘；多机箱盘名前标明机箱编号与盘位，悬停可看机箱坐标。
原有背面贴邻连接继续可用，和导线重复连接时不会重复列盘。

| 硬盘 | 物品容量 | 条目上限 |
| --- | ---: | ---: |
| 64K | 65,536 | 512 |
| 256K | 262,144 | 1,024 |
| 1M | 1,048,576 | 2,048 |
| 16M | 16,777,216 | 4,096 |

每块硬盘最多 128 个目录（含根目录），用途由玩家决定，盘之间不共用容量或目录。
拆除 NAS 掉落硬盘，盘内库存与目录保留，可在同一存档内换机箱使用。
手动跨盘搬运可经过背包，也可通过联网终端发送到对方收件盘；外部物流可通过 0.3.0 的接口接入，尚无直接跨盘拖动。
硬盘的完整数据保存在世界文件中，复制硬盘物品到另一个存档不会携带库存。
操作方法、配方和存档说明见 [NAS 使用说明](docs/nas-usage.md)。

## 外部物流接口（0.3.0）

潜行右键 NAS 或终端的表面安装“文件夹物流接口”，右键接口选择硬盘和目录，
设置允许存入 / 取出及是否包含子目录，然后点击“应用配置”。管道或总线连接外侧中央接口。
接口独占一个相邻方块位置，支持六个方向；目录改名不影响绑定，拔盘或目标失效时暂停存取。
新物品始终进入选定目录，子目录选项只扩展查询与取出范围。

同时更新四档硬盘的金属外壳、容量铭牌像素贴图和金色触点。
配方、连接限制、可选 MEK / AE2 测试和操作方法见 [物流接口使用说明](docs/logistics-usage.md)。
终端间基础发送见 [终端传输说明](docs/remote-transfer-usage.md)，云存储及升级能力仍在 [规划阶段](docs/logistics-plan.md)。

## 基站基础结构

新增七种基站部件，按 **3 × 3 底座、5 格高、17 块** 搭建。细立柱和板式天线在放置时就显示实际模型，
右键控制器可检查缺件、错误朝向和坐标，也可查看逐层搭建指南；拆装部件会重新检查成型状态。
无需供电，绿灯只表示结构完整。同基站终端可直接发送；跨基站需要双方控制器都开启加入网络。
接收终端须主动开放指定收件目录；操作、吞吐限制和保存保证见 [终端传输说明](docs/remote-transfer-usage.md)。
获取方法、朝向和搭建顺序见 [基站使用说明](docs/base-station-usage.md)。

数据导线可接终端、NAS 的任意面及基站背面接口，支持六向连接、转弯、分叉和环路。
悬停终端左上角图标查看连接原因与基站坐标，控制器窗口显示线路状态和终端数量。
同一线路多个基站接口会提示冲突，本版每条连通线路最多 256 段导线。
导线也用于连接机器接口，终端目录中的程序可控制原版熔炉、高炉、烟熏炉和酿造台自动加工。
配方、接线规则和状态说明见 [数据导线使用说明](docs/data-cable-usage.md)。

## 物品搜索（0.4.0）

点击终端顶部“搜索”或按 Ctrl+F。默认搜索当前主存储盘 / 硬盘的全部目录，
点击“全盘”可切换到进入搜索时的当前目录及子目录。输入停顿约 200 毫秒后更新结果。

支持当前客户端语言的名称、自定义名称、注册 ID 和 `@命名空间`，忽略大小写，
多个关键词需同时满足。例如 `铁`、`iron ingot`、`minecraft:iron_ingot`、`@mekanism 铁`。
清空输入显示范围内所有物品；点击退出按钮或按 Esc 返回搜索前的目录和页码。

结果显示名称、数量和来源路径，同种物品在不同目录分别列出，不同附加数据也不合并。
仍可右键取 1 个、Shift 点击取最多 64 个，或使用数量框取出。
选择结果后点击“定位”，或双击结果，会退出搜索、打开来源目录、翻到对应页并高亮条目。
搜索期间暂不能存入、移动或修改目录；先定位 / 退出到普通目录再操作。
操作和范围说明见 [搜索使用说明](docs/search-usage.md)。

## 目录中的自动程序

在终端**本地盘的文件夹**中点击“新建”，把类型切换为“自动程序”，命名并创建。
左键打开程序文件，选择机器、原料目录和样本、燃料或辅料目录和样本、产物目录；保存后填写本次次数并启动。
程序可以改名、复制、移动和删除，最多保存 32 个，不占物品容量；运行中的程序须先取消才能修改、移动或删除。

潜行右键专用的原版**熔炉、高炉、烟熏炉或酿造台**安装“机器接口”，
从接口外侧用数据导线连接一个存储终端。接口提供机器连接和执行能力，运行状态在终端程序窗口中查看。
每次运行 1–4,096 次，机器按原版加工时间和耗材工作。酿造每次处理一瓶药水，辅料目录同时供应酿造材料与普通烈焰粉。
关闭窗口后任务继续；缺料、断线、满盘会暂停，取消时机器中的物品留在原处。

程序文件保存在终端，拆除接口不会删除文件；拆除终端不会把文件带入掉落方块。
旧接口原型任务升级后停止自动控制，已经进入机器的物品和原版加工进度保留，需要手动取出残留物后创建程序文件。
本版仅支持终端本地盘及已加载区块；NAS 取料、队列、多步骤流程与自动合成尚未实现。
工作台自动化留待后续独立的计时自动合成台；终端下方工作台仅提供原版手动合成。
完整操作、接线与异常处理见 [自动程序使用说明](docs/production-program-usage.md)。

## Windows 快速开始

项目内的 `dev.ps1` 自动寻找已安装的 JDK 17，并将 Gradle 缓存放在项目的
`.gradle-user-home/` 中；只在命令执行期间调整环境变量。

```powershell
cd D:\Code\item-exploer
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 build
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 runClient
```

打包输出：`build/libs/itemexplorer-1.20.1-0.4.0.jar`。
将此 JAR 放入安装了对应 Forge 的 Minecraft 1.20.1 实例的 `mods/` 目录。
多人游戏的客户端与服务端都需要安装相同版本。0.4.0 继续读取 0.1.x
使用的终端版本 1 存档及 0.2.x 硬盘数据；网络协议为 12，客户端和服务端应使用同一构建。
`-ExecutionPolicy Bypass` 仅适用于当前 PowerShell 子进程，不修改系统策略。

如果 JDK 17 位于非标准目录，可在当前终端指定：

```powershell
$env:ITEM_EXPLORER_JAVA_HOME = 'D:\your-jdk-17'
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 build
```

## IDE

IntelliJ IDEA：打开项目根目录，作为 Gradle 项目导入。
将 Project SDK 和 Gradle JVM 都设为 JDK 17，Gradle distribution 使用 Wrapper。
Gradle user home 可设为项目内的 `.gradle-user-home`，复用已经下载的依赖。

生成运行配置：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 genIntellijRuns genVSCodeRuns
```

VS Code 需要 Java 和 Gradle 的相应扩展；本项目不自动安装 IDE 扩展。
命令行 `runClient` 不依赖 IDE。

运行库存与菜单的游戏内自动测试：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 runGameTestServer
```

GameTest 使用独立的 `run-gametest/` 世界，测试代码和测试结构不打进发布 JAR。
`build` 只进行构建，不代替 `runGameTestServer`；当前没有普通 JUnit 测试。
GitHub Actions 会在 push / pull request 时执行 `build runGameTestServer`，
保存验证日志，并在全部通过后保存 JAR；也可以手动触发。

独立服务端重启、保存后强杀恢复、真实双客户端 TCP 和界面补充验收的结果、已知问题及复跑脚本见 [0.3.0 补充验收报告](docs/acceptance-2026-09-29.md)。

其他任务：`runServer` 启动独立开发服务器，`runData` 运行资源生成。
客户端使用 `run/`，服务端使用 `run-server/`，数据生成使用 `run-data/`。
首次使用独立服务器时需自行阅读并处理 Minecraft EULA。

## 代码与资源

- `src/main/java/dev/itemexplorer/ItemExplorer.java`：模组入口，客户端和服务端共用。
- `src/main/java/dev/itemexplorer/storage/`：通用存取接口、动态容量、目录和背包转移逻辑。
- `src/main/java/dev/itemexplorer/disk/`：容量等级、磁盘身份和独立世界存档。
- `src/main/java/dev/itemexplorer/block/`：设备方块、存档和拆除掉落。
- `src/main/java/dev/itemexplorer/menu/`：服务端操作校验、原版背包槽位和手动工作台。
- `src/main/java/dev/itemexplorer/network/`：操作请求与分页快照。
- `src/main/java/dev/itemexplorer/client/`：客户端注册和资源管理器界面。
- `src/gametest/`：Minecraft GameTest 自动测试。
- `src/main/resources/META-INF/mods.toml`：模组信息及依赖声明。
- `gradle.properties`：游戏、Forge、模组版本及名称。
- `docs/design.md`：首版设计、数据规则与尚未实现的功能。
- `docs/logistics-plan.md`：物流讨论留档，以及尚未实现的内部无线发送与云存储规划。
- `docs/production-program-plan.md`：[生产程序与外部加工设计](docs/production-program-plan.md)，记录当前范围与历史讨论。
- `docs/production-program-usage.md`：目录程序文件、四种原版生产机器、接线、异常处理及实现边界。
- `docs/logistics-usage.md`：0.3.0 外部物流接口的已实现行为、连接方式和验证方法。
- `docs/search-usage.md`：0.4.0 当前盘物品搜索、匹配规则、定位和实现边界。
- `docs/version-choice.md`：版本选择理由与官方来源。
- `docs/setup-verification.md`：本机环境与当前验证结果。

`All Rights Reserved` 元数据。第三方 MDK 文件遵循其原始许可证。
