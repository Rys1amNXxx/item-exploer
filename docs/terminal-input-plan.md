# 终端操作与原版手势兼容提案

记录日期：2026-10-20。

状态：提案，大部分尚未实施，细节待确认；其中背包区 Shift + 双击批量存入已在 0.5.0-dev 实现。当前实际操作以 [README 的操作表](../README.md#游戏中使用) 为准。
目标版本为 0.5.0-dev：该版本本来就要升级网络协议（当前为 17），在这个版本调整操作习惯，对已有玩家的影响最小。

## 问题

存储终端的右侧物品区是模组自绘的条目格，不是原版槽位。为了实现资源管理器式的功能，
物品区占用了玩家最熟悉的左右键：左键用于选中和拖动，右键直接取 1 个进背包。
习惯原版容器手势的玩家打开终端后，会发现点击含义不同，数字键、Q 等快捷操作也没有反应。

背包、快捷栏和左下方 3 × 3 合成格是原版槽位，原版操作在这些区域基本可用，不在本文的调整范围内。

## 现状对照

以下为物品区的行为，依据 `StorageScreen` 当前的输入处理整理。

| 操作 | 原版容器里的效果 | 当前终端物品区的效果 |
| --- | --- | --- |
| 左键点物品 | 整组拿到鼠标上 | 选中条目；按住拖动可移到文件夹 |
| 右键点物品 | 拿起一半到鼠标上 | 直接取 1 个进背包 |
| Shift + 左键 | 整组转移到另一侧 | 取最多 64 个进背包 |
| 鼠标拿着物品时左键 | 放下整组 | 整组存入当前目录 |
| 鼠标拿着物品时右键 | 放下 1 个 | 整组存入当前目录 |
| 悬停按数字键 | 与对应快捷栏格交换 | 无反应 |
| 悬停按 Q / Ctrl+Q | 丢出 1 个 / 一组 | 无反应 |
| 悬停按 F | 与副手交换 | 无反应 |
| 双击 | 把同类物品收集到鼠标上 | 仅搜索时可用，作用是定位结果 |
| 中键 | 创造模式复制物品 | 整理当前目录 |
| 滚轮 | 原版无；Mouse Tweaks 等用来移动物品 | 翻页 |

Mouse Tweaks、Item Scroller、Inventory Profiles Next 等模组只识别原版槽位，在物品区不起作用。

## 为什么箱子类模组能自动兼容

原版的容器手势分两部分实现：

- **客户端**：`AbstractContainerScreen` 负责识别手势，包括双击、Shift + 双击、拖动均分、数字键、Q 等，
  再把它们翻译成对某个槽位（`Slot`）的点击类型（`ClickType`）。
- **服务端**：`AbstractContainerMenu.clicked` 按点击类型执行拾取、放下、快速转移、交换、丢出、收集同类等操作。

任何放进菜单的原版槽位都会自动获得全部手势，Mouse Tweaks 等模组也是在这一层工作的。因此有两类做法：

| 做法 | 典型模组 | 手势兼容 | 限制 |
| --- | --- | --- | --- |
| 固定数量的原版槽位 | Iron Chests、Sophisticated Storage 等箱子、背包类模组 | 自动继承全部原版手势和依赖槽位的模组 | 每格有堆叠上限，格子数量固定，没有目录和超大数量 |
| 自绘的虚拟列表 | AE2、Refined Storage 等网络存储模组的终端，以及本模组 | 需要逐个重新实现，覆盖范围取决于各模组 | 依赖槽位的模组不起作用 |

本模组的终端界面本身就继承自这两个原版类：下方背包和合成格是原版槽位，所以已经自动获得了全部手势。
只有右侧物品区是自绘的，单个条目可以存放远超 64 个物品，还要随目录和翻页变化，无法直接套用原版槽位。

还有一种折中做法是「虚拟槽位」：把当前页的条目包装成原版槽位，让原版客户端代码负责识别手势，
再在服务端重写 `clicked`，把各种点击类型翻译成库存操作。这样能免费获得手势识别，Mouse Tweaks 等模组也可能生效。
但原版槽位的默认行为都假定数量不超过堆叠上限（例如左键会把整格物品拿到光标上），每种点击类型仍要自己重写；
原版点击包的过期保护也和现在的请求不同，翻页或目录变化后可能作用到玩家没看到的条目上。
本提案暂不采用，但如果后续对模组兼容的需求很强，可以再评估。

### Shift + 双击批量存入

状态：背包区部分已在 0.5.0-dev 实现，网络协议升至 17。

原版流程（依据 1.20.1 `AbstractContainerScreen` 反编译结果）：

1. 鼠标拿着物品时，按住 Shift 点击背包里某一格。**松开鼠标**时转移这一格，并记下这一格的物品种类。
2. 250 毫秒内再次按下并松开同一格，客户端遍历菜单中所有槽位，筛选出与这一格属于同一个容器、
   且能与记下的物品合并的格子，对每一格各发一次快速转移。只会遍历背包和快捷栏，不会扫到合成格。
3. 鼠标空着时，松开鼠标会清零双击计时，所以这个手势只在鼠标拿着物品时生效。

修正前，终端把每次快速转移翻译成一次「存入背包格」请求。这些请求在同一帧发出，
携带的是同一个库存版本号，服务端处理完第一个后版本号改变，其余被当作过期请求拒绝；
服务端每个 tick 也最多处理 10 个请求。按代码推断，修正前只能存入第一组。

现在的实现：

- 客户端把**一次松开鼠标**期间产生的所有背包快速转移收集起来。只有一格时仍发送原来的「存入背包格」请求；
  有多格时合并成一个「批量存入背包格」（`DEPOSIT_SLOTS`）请求，用位掩码列出这些格子。
  这样不需要读取原版的私有双击状态，原版判断有误时也只会退化为普通存入。
- 服务端在一次请求里逐格存入当前目录：容量不足时尽量多存，剩余的留在原格；空格子跳过。
  掩码里有背包以外的格子或便携终端的锁定槽位时，整个请求被拒绝，什么也不改变。
- 这个请求**不校验库存版本号**：它紧跟第一次存入发出，客户端还没收到新版本号；
  从玩家自己背包存入当前目录也不依赖界面上看到的库存内容。菜单会话、挂载会话、锁定状态、搜索模式和每 tick 次数限制仍然校验。
- 自动测试见 `BatchDepositTests`，以及 `PortableTerminalTests` 中锁定槽位的用例。客户端识别手势的部分尚未在游戏中实测。

尚未实现：物品区的 Shift + 双击对应为反方向，把该条目尽可能多地取进背包。

## 设计原则

1. **原版已有的手势保持原版含义。** 玩家在箱子里会怎么操作，在终端物品区就能怎么操作。
2. **资源管理器特有的功能改用原版没有占用的手势。** 包括选中、指定数量、批量移动和程序文件等。
3. **参照 AE2、Refined Storage 网格界面的通行做法**，装过这类模组的玩家不需要重新学。
4. **不提供「经典模式 / 资源管理器模式」切换。** 两套操作逻辑会让测试和维护的工作量翻倍。

## 新的操作方案

### 物品区：鼠标空着时

| 操作 | 新行为 | 说明 |
| --- | --- | --- |
| 左键 | 取出一组（不超过该物品的堆叠上限）到鼠标上 | 原版习惯 |
| 右键 | 取出半组到鼠标上 | 原版习惯；数量向上取整 |
| Shift + 左键 | 取出一组进背包 | 与现在接近；按堆叠上限取，不再固定为 64 |
| 悬停按数字键 1–9 | 取出一组放进对应快捷栏格 | 该格已有物品时的处理见「待确认」 |
| 悬停按 Q / Ctrl+Q | 丢出 1 个 / 一组 | 见「待确认」 |
| 悬停按 F | 取出一组放进副手 | 副手已有物品时与数字键规则一致 |
| Ctrl + 左键 | 选中条目，不取出 | 选中后的用法见下文 |
| 中键 | 整理当前目录 | 保留现状，与整理类模组的习惯一致 |
| 滚轮 | 翻页 | 保留现状 |

### 物品区：鼠标拿着物品时

| 操作 | 新行为 |
| --- | --- |
| 左键物品区空白处或任意条目 | 整组存入当前目录 |
| 右键物品区空白处或任意条目 | 存入 1 个 |
| 左键 / 右键文件夹格、左侧目录树或上方路径 | 整组 / 1 个存入**该文件夹**，不进入文件夹 |

最后一行就是新的「移动」：在一个目录里拿起物品，点左侧目录树的另一个文件夹放下，即完成一次移动。
它不需要先选中、也不需要填数量，适合一组以内的日常整理。

### 选中、指定数量与批量移动

超过一组、或需要精确数量的操作，保留现有流程，只把选中手势从左键改为 Ctrl + 左键：

1. Ctrl + 左键选中条目。
2. 在数量框填写数量，或点「全部」。
3. 点「取出」，或点「移动到…」后选择目标；也可以把选中的条目拖到目录树、文件夹格或路径上。

拖动只对已选中的条目生效，避免和「左键拿起」冲突。

### 文件夹格与程序文件

- 鼠标空着时左键文件夹格：进入该文件夹（不变）。
- 程序文件：保持现有的左键打开、右键选中。程序文件不是物品，没有原版手势需要兼容。

### 不变的部分

- 背包、快捷栏与合成格的全部原版操作，以及 Shift 点击背包物品存入当前目录。
- Ctrl+F 搜索、双击搜索结果定位。
- 中键整理、滚轮翻页。

## 特殊模式下的规则

### 搜索模式

搜索结果只允许从当前已发布的结果页取出，并拒绝存入和移动，这条服务端规则不变。
因此搜索模式下：

- 左键 / 右键 / Shift + 左键 / 数字键取出，沿用和普通模式相同的手势，走现有的搜索取出请求（TAKE），由服务端校验结果页。
- 鼠标拿着物品时点击物品区不存入，与现在一致。
- 双击仍为定位。由于左键改为拿起，需要确认双击第一下拿起的物品如何处理，见「待确认」。

### 便携终端

便携模式下，手持的便携终端所在的槽位被锁定，现有规则禁止对它进行拾取、交换、丢出或存入。
新的数字键和 F 键操作必须遵守同一限制：目标是被锁定的快捷栏格或副手时，直接拒绝。

## 服务端与协议影响

当前取出（`WITHDRAW`）只把物品放进背包，存入光标物品（`DEPOSIT_CURSOR`）只能整组存入当前目录。
新方案需要：

| 新增或调整的动作 | 用途 |
| --- | --- |
| 取出到光标 | 左键 / 右键拿起；数量由客户端给出，服务端按堆叠上限截断 |
| 取出到指定槽位 | 数字键与 F 键；校验槽位范围与便携锁定槽位 |
| 丢出 | Q / Ctrl+Q；在玩家位置生成物品实体 |
| 存入光标物品增加数量和目标目录参数 | 右键存入 1 个；点文件夹存入该文件夹 |
| 批量存入背包格（已实现） | 背包区 Shift + 双击；一次请求完成，不再逐格发送 |

要求与现有请求一致：

- 校验菜单会话、库存版本、挂载会话和玩家距离；过期或重放的请求不能取出物品。
- 取出到光标时，光标必须为空，或与取出物品可合并且不超过堆叠上限；失败时库存与光标都不变。
- 网络协议版本再升一级（批量存入已升到 17）。
- 每个新动作都补充 GameTest：数量守恒、过期请求、关闭菜单后的迟到请求、断线时光标物品只掉落一次、便携锁定槽位、搜索模式限制，以及批量存入在容量不足时的部分存入。

## 刻意不做

- **不把条目改成原版槽位。** 单个条目的数量可以远超 64，硬套原版槽位很别扭；AE2 也没有这样做。
  代价是 Mouse Tweaks 一类依赖槽位的模组仍不作用于物品区。
- **不提供操作模式切换**，原因见「设计原则」。
- **不改动背包和合成格**，它们已经是原版槽位。

## 待确认

1. **选中手势**：Ctrl + 左键，还是 Alt + 左键？Ctrl + 左键在部分整理模组中另有用途。
2. **右键数量**：鼠标空着时取半组（原版习惯），还是取 1 个（现有行为）？本文暂定半组。
3. **数字键 / F 键遇到已有物品的格子**：按原版交换（格子里原有的物品存入当前目录），还是只在格子为空或可合并时取出、否则拒绝？
   交换需要在一个请求里完成存入和取出，并保证失败时都不发生。
4. **Q 丢出**：是否允许直接从终端丢物品？它能用，但容易误触丢失贵重物品。
5. **搜索模式下的双击**：第一下会拿起物品。是改为「双击时把第一下拿起的物品退回并定位」，还是把定位改到 Ctrl + 左键或单独的按钮？
6. **鼠标拿着物品时点文件夹格**：存入该文件夹（本文方案），还是仍然进入文件夹？前者便于移动，后者与当前行为一致。
7. **Shift + 双击背包物品**：已按「Shift + 双击批量存入」一节修正，客户端手势识别还需要在游戏中实测。
