# 基站基础结构使用说明

实际游戏画面与测试记录见 [2026-09-30 基站验收](verification/2026-09-30/base-station/README.md)。

当前版本包含基站部件、实际方块模型、合成配方、结构检查与搭建指南。
2026-10-01 已增加 [数据导线与终端接入](data-cable-usage.md)，基站窗口会显示真实的本地有线接入状态。
已加入 [终端传输](remote-transfer-usage.md)：同基站内直接发送，不同基站需要双方控制器都开启加入网络。
控制器绿色灯只表示结构完整；不需要能量，也没有供电端口。接收终端需另外开放收件目录。
0.5.1-dev 在控制器正面增加独立青色无线联网灯：结构完整且已开启加入网络时亮起，关闭无线或结构失效后熄灭。
结构绿灯与无线灯分别显示，开启无线的设置仍会保留；修复结构后无线灯会自动恢复。联网灯不代表接收终端已开放收件。
0.5.0 增加区块维持模块，可在玩家离开后保持基地的 3 × 3 区块加载；默认关闭，需要在控制器主动开启。

## 获取部件

在创造模式“物品资源管理器”分页中找到以下部件，也可用原版材料合成。

| 部件 | 一座基站需要 | 注册 ID |
| --- | ---: | --- |
| 基站机壳 | 5 | `itemexplorer:base_station_casing` |
| 基站控制器 | 1 | `itemexplorer:base_station_controller` |
| 基站网络接口 | 1 | `itemexplorer:base_station_network_port` |
| 空白扩展模块 | 2 | `itemexplorer:base_station_module` |
| 区块维持模块 | 可选 1 个，替换一个空白模块 | `itemexplorer:base_station_chunk_loader` |
| 信号立柱 | 3 | `itemexplorer:base_station_mast` |
| 天线板 | 4 | `itemexplorer:base_station_antenna` |
| 天线顶帽 | 1 | `itemexplorer:base_station_cap` |

例如 `/give @s itemexplorer:base_station_controller`。
机壳每次合成 6 个，立柱每次 3 个，天线每次 4 个；其余每次 1 个。
控制器、网络接口和空白模块的配方会消耗机壳，制作材料时需另外准备这四个机壳。
配方可从原版配方书查看；拿到铁锭、机壳或铁栏杆后会解锁相应配方。

## 搭建

完整结构占地 **3 × 3 格，高 5 格，共 17 个方块**。底座正面放控制器，
控制器放下时朝向玩家，整座基站可朝任意水平方向。不要求特定地基或露天环境。

下面是底座俯视图，上方为背面、下方为正面。立柱必须放在中央机壳正上方。

```text
机壳    网络接口    机壳
模块    中央机壳    模块
机壳     控制器     机壳
```

1. 铺好完整九格底座。网络接口面朝背面，两个模块的面板分别朝左右外侧；模块位可使用空白模块或区块维持模块。
2. 在中央机壳上竖直放三段信号立柱。
3. 在最上段立柱四个水平邻格各放一块天线板，板面朝外、安装臂朝中心。
   对着立柱水平侧面放置天线板会自动取得相应朝向。
4. 在最上段立柱上方放顶帽。
5. 右键控制器检查；正确部件达到 **17 / 17** 后，面板绿灯点亮。

网络接口、模块、天线等部件可用 **空手潜行右键** 每次水平旋转 90°。
控制器右键始终打开检查窗口；需要改变基站正面时拆下控制器重新放置，并调整其他部件。

每个部件放下时已经显示自身模型。立柱只有柱芯和连接圈，天线为薄板与短臂；
它们虽然看起来较细，仍各自占一格，不能与其他方块共用位置。
正确朝向的天线邻接立柱时，立柱相应一侧会显示连接臂，拆除或转错天线后连接臂消失。

右键控制器后的“搭建指南”可查看五层格位及符号说明。
仓库中的 [逐层搭建图](concepts/base-station-v1/structure.png) 也可对照使用。
最初的概念效果图存在底座分格误差，以逐层图和实际游戏部件为准。

## 检查与拆除

检查窗口显示匹配部件数，并逐项列出问题部件的世界坐标：

- **缺少部件**：所需位置为空。
- **方块类型不符**：该位置放了其他方块。
- **朝向不符**：控制器、接口、模块或天线没有朝预期方向。
- **所在区域未加载**：检查所需的区块当前不可用。

部件拆装与空手旋转会刷新成型状态，另有每 20 tick（正常运行约一秒）的兜底复核。
缺件位置上的普通方块发生变化时，最迟在周期复核或下次打开窗口时更新诊断。
成型状态是现场计算结果，不会仅凭保存的旧灯色认定结构有效。
基站检查本身不会强制加载区块；启用的区块维持模块另行管理加载范围。

拆除部件按原版正常掉落规则返回相应方块。基站本身没有库存，拆除不会搬运或复制物品。
当前只验证 17 个必需格位，不把其他空格或天空可见度当作成型条件；
装饰方块可自由布置，但可能遮挡天线、控制器或操作位置。

## 区块维持模块（0.5.0）

用 **2 个金锭、1 个末影珍珠、2 个红石粉、1 个空白扩展模块和 1 个红石比较器**合成一个区块维持模块。
拿到空白扩展模块后解锁配方。模块面板上的九格标记对应 3 × 3 区块范围，中间金色格代表控制器所在区块。

```text
金锭   末影珍珠  金锭
红石粉 空白模块  红石粉
空     比较器    空
```

1. 把基站底座左侧或右侧的一个空白模块换成区块维持模块，面板仍朝外。装一个就足够，两个不会扩大范围。
2. 确认基站完整，右键控制器，点击顶部“区块维持”。
3. 点击“区块维持：已关闭（点击开启）”，等状态显示“正在维持 9 个区块”。
4. 检查窗口显示的 X、Z 方块坐标范围；把固定终端、NAS、需要持续运行的机器和整段连接导线放在范围内。
5. 点击“显示世界边界 60 秒”，关闭窗口查看金色的控制器区块及青色的周围区块；再次点击可提前隐藏。

范围以**控制器所在区块**为中心，是 48 × 48 格的正方形，覆盖世界的整个高度。它不以控制器方块为中心计算 24 格半径。
边界预览只是客户端显示，不会开启加载，也不会验证范围外的设备；实际加载状态以控制器窗口为准。
范围外的设备和导线仍可能卸载，区块维持模块不会自动沿线路扩展范围。

区块维持与“无线联网”是独立开关：维持区块不要求基站加入无线网络；使用便携终端仍须另外开启无线联网和终端的便携访问。
无需供电或燃料。世界运行期间持续维持，关闭控制器开关、拆除最后一个维持模块、转错模块朝向或破坏基站结构后释放本基站的加载。
其他基站或其他加载器仍维持的重叠区块不受影响。已开启设置随世界保存，正常重启时会重新验证结构和模块，恢复有效基站的加载。
修复结构后，基站所在区域保持加载且有可用名额时会重新开始维持。

窗口会分别提示开关关闭、缺少模块、结构不完整、结构所在区块未加载、达到服务器上限和加载失败。
已开启但暂时不可用时，仍可在窗口关闭开关；仅有完整结构并安装维持模块时才能从关闭切换为开启。

服务器配置位于世界目录的 `serverconfig/itemexplorer-server.toml`：

```toml
[stationChunkLoading]
maxActiveStations = 16
```

该上限对所有维度合计，默认最多 16 座运行中的维持基站，每座固定维持 9 个区块；范围重叠的基站仍各占一个名额。
设为 `0` 可禁用本模组的区块维持。达到上限的基站显示等待名额，在其区域仍加载且有名额时重试。
跨维度便携访问、可变半径和打开掌机才唤醒基地的模式尚未加入。

## 当前边界

- 空白模块没有升级效果；区块维持模块可替换空白模块。跨维度、连接数量和吞吐量模块尚未实现。
- 基站网络接口外侧可接数据导线；不连接第三方管道，不暴露物品库存。
- 原有“文件夹物流接口”继续负责第三方物流，与本次新增部件分工不同。
- 不会把两地生产机器网络合并，不会自动打开库存权限，也不会创建云盘。
- 检查界面显示有线状态和终端数量，支持多人分别查看，并提供加入/退出同维度公共网络的开关。
- 控制器默认退出无线网络，这不会阻止同基站本地发送；本版没有网络分组或配对功能。

完整方向见 [物流规划](logistics-plan.md)，外观原稿见 [基站设计记录](concepts/base-station-v1.md)。

## 开发与验证

游戏资源由原生像素与模型脚本生成：

```powershell
node scripts/generate-base-station-assets.mjs
node scripts/check-base-station-models.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 build runGameTestServer --console=plain
```

专用 GameTest 覆盖四种朝向、17 个部件逐一拆装、错误朝向和错误部件、未加载位置不读取、
重载复核、立柱连接、细模型碰撞/面剔除与掉落。它们随其他存储测试运行，不包含在发布 JAR 中。
区块维持测试另行覆盖实际 Forge 票据、重叠归属、模块移除、全服额度，以及陈旧或远距离控制器请求。

区块维持的独立重启验收会在 `work/chunk-loading-restart/` 下新建测试世界，先保存并停止服务器，再用另一 JVM 启动同一世界：

```powershell
pwsh -NoProfile -File scripts/verify-chunk-restart.ps1
```

它验证没有玩家时远端熔炉仍运行、跨区块基站自动恢复、缺失票补齐、无效票清理，以及重启后的便携终端和 NAS 存取。
真实中文界面和边界预览另用 `scripts/chunk-client-test.init.gradle` 运行，输出位于 `work/chunk-loading-client/`；
该探针从已有的 `work/remote-transfer-client/saves/Base Station Probe` 复制独立测试世界。

可选客户端探针需要先在 `work/base-station-client/saves/Base Station Probe` 准备独立测试存档，
并让该运行目录的 `options.txt` 使用 `zh_cn`；不会自动创建或选择普通游玩存档。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 runClient --init-script scripts/base-station-client-test.init.gradle --console=plain
```

此命令运行隐藏的验收客户端，校验真实模型烘焙、贴图引用与检查窗口同步，
截图并写入 `work/base-station-client/report.txt` 后自动退出；不能用它代替正常游玩的 `runClient`。
它只在严格校验测试世界路径后修改场景，测试代码不会打进发布 JAR。

正式模型的离线预览可用 `python scripts/preview-base-station-models.py` 生成，
需要 Pillow 与 NumPy；它直接读取游戏 JSON 和贴图，但不模拟 Minecraft 环境光照。
