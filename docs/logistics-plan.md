## 讨论时的基础（0.2.0）

0.2.0-dev 已有存储终端、四盘位 NAS、独立硬盘、目录管理和同存档搬盘。
`StorageAccess` 已提供模拟与实际存取，终端正在使用；当前没有注册外部物品物流 capability。
直接跨盘转移、外部管道接入、无线发送与云存储均未实现。

现有磁盘身份、挂载会话和库存校验可以复用，但不会自动提供跨设备事务或崩溃恢复。

## 本轮讨论方向

1. 优先考虑兼容已有自动化模组，以 MEK 与 AE2 为首批对接、验证目标。
2. 独立物流接口方块目前定位于外部模组兼容，供其他模组管道或总线访问库存。
3. 站间物流采用无线方向，由存储终端发起；终端以导线接入本地基站，贴近 Windows 资源管理器操作。
4. 玩家可以像发送文件一样，将物品发送到另一台存储站；内部发送不要求经过外部物流接口方块。
5. 后续可能加入云存储概念。云存储的具体实现和玩法尚未确定，不作为首版物流承诺。

本文“存储站”是玩家操作的终端及其可访问库存的概念，具体远端寻址对象仍待设计。
无线方向用于基站之间的远程链路，终端接入基站使用导线；本地生产网络另有有线连接建议。
当前终端与 NAS 的相邻连接保持既有行为。

## 外部物流兼容建议

### 通用接入口

建议以 Forge 1.20.1 的 `IItemHandler` / `ForgeCapabilities.ITEM_HANDLER` 为基础提供统一物品接口，
再针对实际模组和版本验证行为。基础兼容保持模组可以独立使用，不强制依赖 MEK 或 AE2。

| 对接设备 | 计划支持的行为 |
| --- | --- |
| MEK 物流管道 | 向开放范围存入，或从允许输出的范围抽取 |
| AE2 输入总线 | 从本模组开放的库存抽取物品，送入 ME 网络 |
| AE2 输出总线 | 从 ME 网络取物，存入本模组指定目标 |
| AE2 存储总线 | 让 ME 网络直接查询和存取开放范围，物品仍归本模组库存所有 |

AE2 的输入 / 输出以 ME 网络为参照。连接本模组接口时仍使用 AE2 自身的相应总线。
以上是兼容目标，不代表当前已通过兼容测试。

设计时应考虑存储总线对库存可见性的要求：如果只暴露缓冲槽，外部通常只能看见缓冲库存。
不能把“能通过缓冲槽运输物品”当作“能通过 AE2 浏览全部开放库存”。
稳定槽位、动态条目映射、大数量展示及查询成本需要在实现阶段确定并验证。

### 独立物流接口方块与配置界面

当前建议采用独立接口方块，右键接口配置其目标和存取范围。

| 部件 | 建议职责 |
| --- | --- |
| NAS | 装载硬盘、提供库存、显示盘位状态 |
| 存储终端 | 浏览和整理目录、发起内部无线发送；后续可集中管理接口 |
| 物流接口 | 向外部管道或总线开放指定库存，保存独立的接入配置 |

终端集中配置页面属于后续建议，现场右键接口的方式可以保留。
相比在 NAS 上统一按面配置，独立接口更方便玩家将现场管线与规则对应；代价是额外方块、空间和合成成本。
NAS 按面配置曾作为备选讨论，尚未实现。

首版可先要求接口紧贴 NAS，具体连接方式待确认。相邻方案仍受 NAS 周围可用位置限制，
独立接口方块本身不会消除这一限制；接口扩展方式以后另行设计。

### 文件夹绑定与默认规则

建议第一版同时支持根目录和指定文件夹存取，使简单收集与自动归档都能使用。

- 每个接入口绑定指定硬盘与文件夹；选择硬盘后，默认目标为该盘根目录。
- 提供“允许存入”和“允许取出”开关，组合为仅输入、仅输出或双向。
- 默认只访问选中文件夹直接包含的物品；“包含子文件夹”需明确开启。
- 包含子文件夹时，查询 / 输出可以递归覆盖子目录，输入仍进入选中的文件夹。
- 选择根目录并开启包含子文件夹，可表达整块盘的开放范围；不默认开放其他硬盘。
- 配置持久保存在接入口，不跟随玩家在终端当前浏览的文件夹变化。
- 绑定使用稳定磁盘 ID 与文件夹 ID，改名不改变目标。
- 目标盘离线、目录被删除或库存进入保护状态时暂停对应存取，不静默切到根目录或其他盘。
- 显示连接状态和无法操作的原因，例如硬盘离线、目录不存在或容量已满。

示例：冶炼线直接输入“材料盘 / 金属 / 铁锭”，加工线只从这个目录抽取；
“工程盘 / 铁路工程”中的预留铁锭不因同种物品而被其他入口抽走。

首版建议让外部管道和总线承担其已有的物品过滤功能。
按物品 / 标签自动分类、最低保留数量、优先级和满盘转投属于后续扩展；
不根据盘名、目录名或其他目录中存在同种物品，就隐式推断输入目标。

## 内部无线发送建议

### 基站接入与基础功能

以下为 2026-09-30 用户明确的设计方向，尚未实现：

- 玩家在世界中搭建信号塔 / 信号基站形式的多方块结构，名称和外观待定。
- 终端通过导线连接有效基站后才能接入远程网络，向其他联网终端发送或接收物品；两端均需具备接入条件。
- 首先完成基础收发功能，跨维度升级留待后续。
- 后续通过在基站结构中加入更多或不同的功能方块，改变或升级跨维度能力、连接数量和吞吐量。
- 当前不引入能量系统，不给基站、导线或远程物品传输增加供电和能耗要求。

首版建议从同维度收发开始，形成完整流程：结构成型识别、有线接入、目标终端发现、选择物品与数量、
交付到接收目录，以及断线、目标离线、满盘等状态反馈。此处不承诺具体结构尺寸、配方或参数。
基础版仍需明确默认连接与传输上限；“暂不做升级”不表示这些数值无限制。

同维度是否不限距离、一座基站可接入多少本地终端、连接数量具体统计本地终端还是远端链路，
以及不同规格基站互联时如何确定可用能力，仍需设计。
建议首版不强制加载区块，设备未加载时拒绝新发送并保留源端物品；该离线处理方式尚未定稿。

实现时应将基础结构识别与能力计算分开，使后续功能方块可以扩展能力。
结构拆除、改建或升级后如何重算连接、处理超限连接及尚未完成的传输，也需补全规则。
基站负责远程接入，不因此合并两地的生产控制网络或自动开放全部库存；云盘归属仍另行设计。

### 交互方式

- 存储站可命名，在终端增加“网络位置”或“其他存储站”等入口；具体名称待定。
- 选择物品与数量，通过“发送到”选择目标站。
- 常用目标可以收藏；后续可支持拖到网络位置，以及剪切 / 粘贴式操作。
- 接收站开放接收并指定收件目录，根目录可作为初始选项，也可以使用玩家创建的“收件箱”。
- 默认发送到接收方指定目录；只有对方明确开放其他目录时，发送者才可选择那些目录。
- 自有多站点可考虑开放更完整的远端目录访问，身份与权限规则待定。

以上目录与交互规则属于建议。第一步可先实现“选定数量发送到另一台站的收件目录”，
无需同时完成远程浏览、拖放、批量发送或自动周期发送。

### 转移语义

发送属于真实物品移动：成功转移的数量从源扣除并进入目标，保持总量守恒。
剪切 / 粘贴、跨站拖动同样表示移动；“复制”可用于目录结构和分类规则等配置，不能凭空复制物品。

每次执行应重新验证源与目标的身份、在线状态、挂载关系、访问范围和容量。
现有单盘模拟存取不能直接视为跨站原子事务；跨盘、跨站的实际转移与恢复机制需单独设计。
容量不足时部分成功还是整批拒绝、目标离线时失败还是等待、如何显示进度与取消，均尚未定稿。

## 后续云存储概念

建议将“发送物品”和“访问云盘”区分为两种行为：

| 行为 | 建议语义 |
| --- | --- |
| 发送物品 | 从源库存转移到另一站点的目标库存 |
| 访问云盘 | 多个授权终端访问同一份共享库存，物品归属云盘 |

云盘可考虑作为终端左侧与本地盘、NAS 硬盘并列的存储位置，沿用目录与存取操作。
应只有一份权威库存，不通过给每个终端复制一份内容来实现共享。

这只是云存储的建议解释。是否采用共享逻辑卷、依托某台物理设备、怎样扩容和管理所有者，
以及是否支持跨维度，仍需继续讨论。此处不默认承诺外部互联网服务或跨存档同步。

## 建议实施顺序

1. 外部兼容：确定接口方块与目录绑定规则，完成标准物品接口，验证 MEK 管道及 AE2 三类总线。
2. 基站与内部无线发送：先完成基础多方块、有线接入与同维度指定数量收发及失败处理；跨维度、连接数量和吞吐量的结构升级后续再做。
3. 终端交互完善：按需要增加网络位置、收藏、拖放、剪切 / 粘贴与接口集中管理。
4. 云存储：在共享库存归属、权限、容量和离线规则确定后单独实施。

上述顺序是建议，不代表已安排开发任务或确定版本号。
实现前应设计并验证数量守恒、模拟无副作用、满盘、拔盘、目标失效、并发存取及卸载重载等情况，
并明确正常保存与进程崩溃时各自能够提供的保证。

## 后续待定问题

- 接口方块如何连接 NAS，是否允许接入终端本地盘，以及数量和空间限制如何扩展。
- 接口是否使用缓冲库存，怎样同时满足外部运输与存储总线查询需求。
- 基站基础结构、导线连接面、距离、默认连接与吞吐上限、合成成本，以及目标发现与稳定身份规则。
- 后续功能方块的类型、数量、能力组合及结构改建后的任务处理；跨维度作为后续升级，当前不规划能耗。
- 未加载区块和离线目标的处理方式，是否排队，以及等待期间的物品归属。
- 接收授权、多人共享、目标容量不足、部分成功、取消及失败反馈。
- 云盘的物理依托、容量来源、所有权、访问权限、离线行为与持久化方式。
- 内部自动化发送、物品分类规则、最低保留数量和批量操作是否进入后续版本。
