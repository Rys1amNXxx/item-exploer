# 生产程序与外部加工设计

记录日期：2026-09-30。

状态：讨论留档。本次仅保存设计，不实现功能，也不确定发布版本。
本文区分用户已经明确的功能边界与讨论中的建议；程序文件、生产网络和自动取料不能据此视为已经可用。
现有文件夹物流接口的实际行为见 [物流接口使用说明](logistics-usage.md)。

## 目标与功能边界

在资源管理器式终端中，让玩家把可重复的制作过程保存为目录里的“程序文件”，
需要时打开程序、指定执行次数，由生产系统安排材料和外部机器完成加工。

| 内容 | 本轮结论 |
| --- | --- |
| 目录中的制作程序 | 用户提出的功能方向：保存可命名的流程，运行时选择重复次数 |
| 首批外部加工设备 | 用户明确先适配原版熔炉；其他机器不计入首批适配承诺 |
| 终端内置合成界面 | 用户明确只供玩家手动合成，相当于集成一个原版工作台 |
| 自动化合成 | 留给后续独立自动合成台方向，具体设备与实现时间尚未确定 |
| 程序自动取料 | 本轮提出的配套能力：从指定库存取得原料和燃料，完成后归档成品；尚待开发 |
| 机器连接 | 当前建议采用生产控制接口、物流数据线和机器接口；具体结构与参数待定 |

终端的手动合成界面与生产程序是两项独立功能。手动界面提供 3×3 合成格和结果格，
由玩家放入材料、取出结果，不承担后台任务或程序重复执行。
手动界面在终端中的位置、快捷操作和关闭时剩余材料的处理方式，另行设计。

烧制、炼药和多步骤制作都属于长期方向。本轮优先记录原版熔炉的完整生产流程，
不把酿造台、烟熏炉、高炉或任意模组机器一并视为已确定的首版范围。

## 程序文件与运行任务

程序文件保存制作规则，不是操作系统的可执行文件。建议通过图形界面选择配方、设备和目录，
玩家不需要编写代码。`玻璃生产.exe` 只是本轮讨论的命名示例，文件后缀、图标及实际存储格式待定。

建议将程序定义与运行任务分开：

- 程序定义保存步骤、所用设备、材料来源和产物去向，可以再次运行。
- 每次运行生成独立任务，保存执行次数、当前步骤、已投入材料和已收回产物等进度。
- 复制程序只复制规则，不复制原料、任务中的物品或成品。
- 建议将“执行 N 次”解释为完整流程重复 N 轮，同时展示预计产量；最终交互需在实现前确认。

首版建议使用玩家明确配置的固定配方。后续可增加按顺序执行多个步骤；
“只指定最终产物，系统自动寻找中间配方和加工路线”属于另一套自动规划能力，不随程序功能自动包含。

## 外部机器连接建议

建议新增如下连接关系，名称均为暂定：

```text
终端 / NAS
    │
生产控制接口
    │
物流数据线 ── 机器接口 ── 原版熔炉 A
    │
    └──────── 机器接口 ── 原版熔炉 B
```

| 部件 | 建议职责 |
| --- | --- |
| 终端 | 编辑程序、发起任务、查看设备和生产进度 |
| NAS / 终端本地盘 | 提供明确授权给任务的原料、燃料和输出目录 |
| 生产控制接口 | 接入机器网络，管理任务队列、设备占用和运行状态 |
| 物流数据线 | 建立可分叉的连接，同时承载控制通信和沿线的物品转移 |
| 机器接口 | 紧贴目标机器，按设备类型处理输入、燃料、输出和状态反馈 |

建议让一套物流数据线完成送料、收货和状态反馈。机器仍在世界中真实加工，
保留其加工时间和燃料消耗；导线不额外提供电力。
2026-09-30 用户明确本模组当前不接入能量系统，因此生产网络不增加供电或能耗要求。
原版熔炉仍消耗原版燃料；后续若适配需要电力的第三方机器，其供电仍由所属模组处理，
生产网络负责投料、回收和状态反馈，不承担供电。

建议导线本身不保存库存，物品只存在于源库存、接口缓冲区或机器内。
接口是否设置缓冲、容量多少以及拆除时如何处置，属于实现前需要补全的细节。
线缆的外观、距离、吞吐量、网络规模、合成成本和连接面规则尚未确定。

首版可先限制为同维度、一个网络一个生产控制接口、一台机器同时占用一个任务。
线路允许分叉，多台机器各自执行任务；自动分配到“机器组”和负载均衡可后续讨论。
多个控制接口连入同一网络时应有明确反馈，具体冲突规则待定。

当前文件夹物流接口只向漏斗、管道或总线开放绑定目录的物品存取，不能直接管理加工任务。
生产控制接口与机器接口需要新增相应能力，不能把被动物品接口当作已经具备机器控制功能。
现有接口的外观和部分校验逻辑可以复用，是否合并物品种类仍待设计。

此处有线网络针对外部机器生产。此前 [物流规划](logistics-plan.md) 中存储站之间的无线发送，
已明确为终端有线接入多方块基站、基站之间无线通信，其接入职责与机器生产网络分开。
基站的跨维度、连接数量和吞吐量升级通过结构内功能方块扩展；先完成基础功能，不引入能耗。
远程连接不会自动把两地生产控制网络合并，导线的共用与连接规则仍待实现设计。

## 自动取料与熔炉运行示例

程序应能自动从终端可访问的指定库存取得所需物品，玩家无需为每一轮手动搬料。
建议明确绑定原料目录、燃料目录和输出目录，不随玩家当前浏览的文件夹变化，
也不因指定目录缺料而擅自使用其他目录的库存。

目录绑定应使用稳定身份，目录或磁盘改名不改变目标。机器同样需要稳定绑定，
拆除后在相同位置放上另一台机器时，不能只凭坐标就继续旧任务。
首版可先限定单盘内多个目录；是否包含子目录、支持跨盘取料，以及多种燃料的选择顺序待定。

示例程序如下，路径和设备名称仅用于说明：

```text
程序名称：玻璃生产.exe
配方：沙子 → 玻璃
加工设备：玻璃熔炉
原料目录：材料盘 / 原料 / 沙子
燃料目录：材料盘 / 燃料
输出目录：材料盘 / 建材 / 玻璃
执行次数：32
预计产量：32 个玻璃
```

建议运行流程：

1. 检查绑定设备、磁盘和目录是否可用，展示材料需求、缺料和输出空间情况。
2. 按批次预留或取出材料，防止多个任务重复占用同一份库存。
3. 检查熔炉残留物和可用槽位，将本批原料及所需燃料送入机器。
4. 等待熔炉真实烧制，回收属于本批任务的产物，并处理需要返还的容器。
5. 成品进入指定输出目录后更新已完成数量，继续下一批，直到达到执行次数。

燃料需求不能简单等同于制作次数，需考虑熔炉剩余燃烧时间、燃料种类和批量加工。
燃料容器返还、烧制经验的归属和具体补料策略，应在原版熔炉适配时补全。

终端可增加设备管理和任务列表：设备显示名称、类型及在线状态；任务显示进度与等待原因。
“缺少沙子”“燃料不足”“输出目录已满”“机器连接中断”应可区分。
窗口位置和呈现形式尚未确定。建议关闭终端界面后任务仍由服务端管理，
但不默认强制加载区块，也不等同于玩家离线后所有设备都能持续工作。

## 物品归属与异常处理要求

以下是待实现与验证的约束，不表示现有存储接口已经提供了生产事务或崩溃恢复保障。

- 原料、任务缓冲、机器中的材料、成品和容器副产物都必须有明确归属，转移不能复制或吞掉物品。
- 预览和模拟检查不能代替实际执行校验；每次转移都需重新验证设备、挂载、目录、数量和容量。
- 建议缺料、输出满、拔盘或区块卸载时停止进一步投料，并保留尚未交付的物品及任务状态。
- 断线只意味着送料和收货中断。已加载的熔炉可能继续烧制，不能立即退回已经投入的原料。
- 建议取消时只退回尚未消耗的材料，已产生的成品保留；机器里的在制材料需要单独结算。
- 一台机器只分配一个任务，不代表已经阻止玩家、漏斗或其他管道干预。首版需要明确机器专用规则或可靠的访问隔离方式。
- 不能仅凭输出槽出现同种物品就认定本任务完成。发现非预期库存变化时，应停止继续投料并提示核查；仅靠变化检测也无法保证识别所有外部干预。
- 任务需要稳定身份和持久化进度，重复点击、重连和正常重启不能重复扣料或发放成品。

磁盘数据、任务状态和机器方块实体可能分别保存。跨数据文件的恢复机制需要专门设计，
并区分正常保存重启、保存中断和进程崩溃能提供的保证，不能直接沿用单盘模拟存取的结论。

第三方机器可能按不同面开放不同槽位。通用物品接口提供存取能力，
但不会统一说明配方、加工完成条件或产物属于哪个任务；后续兼容必须逐种验证，
不能承诺一个机器接口贴在任意一面即可控制所有机器。

## 建议实施顺序与待定事项

1. 明确程序数据、目录绑定、设备身份、任务状态与物品暂存规则。
2. 完成最小机器连接和原版熔炉闭环：配置固定配方、选择次数、自动取料、补燃料、回收与状态反馈。
3. 验证并发、缺料、满盘、断线、取消、拆除与保存恢复，再考虑扩大设备和流程范围。
4. 后续讨论多步骤流程、酿造台及独立自动合成台；自动合成设备复用取料、调度和归档能力。

终端内置手动工作台可独立设计，不作为熔炉程序的执行器，也不要求先完成自动合成系统。
以上为实施建议，不表示已经排期。

实现前仍需确定：

- 程序文件的数据格式、条目与容量计数、复制移动行为，以及运行期间修改定义的处理方式。
- 原料是否整单预留或逐批预留、批次大小、子目录与跨盘范围、燃料选择和输出空间预留。
- 导线和两个接口的最终形态、配方、缓存、性能上限、加载范围与多人访问规则。
- 机器专用模式或访问隔离的实现，残留物、人工操作、其他管道干预和拆除替换的处理。
- 次数上限、暂停与取消的具体语义、长时间等待和任务恢复规则。
- 手动工作台的界面位置与原版交互细节；后续自动合成台的成本、速度和批量能力，当前不规划供能系统。

最小验收应覆盖完整熔炉流程与数量核对，以及重复请求、多任务竞争、缺料、燃料容器、
输出满、拔盘、目录失效、断线恢复、取消中途加工、设备拆除替换、外部干预和正常保存重启。
异常中断恢复需要独立验收；在结果明确前不宣传为已具备的能力。
