# 首版设计与实现

## 产品目标

玩家合成、放置一个独立存储设备，通过资源管理器式窗口存取物品、创建文件夹、移动分类。
不依赖 AE2，不要求前置科技流程。初版已将方块、库存、存档、网络和界面接通。

## 数据规则

- `StorageInventory` 是服务端持有的库存，不使用客户端展示数量执行转移。
- 每个条目保存稳定 ID、所属目录、数量和一个完整 `ItemStack` 样本。
- 使用 Forge 的 `ItemStack.isSameItemSameTags` 匹配物品，包括物品、NBT 和能力兼容性。
- 只在同一目录内合并相同物品；跨目录允许同种材料按数量分配。
- 设备共享 4,096 件物品容量，最多 128 个条目、64 个目录（含根目录）。
- 目录最多嵌套 8 层，名称最多 24 个 UTF-16 代码单元；同级名称不区分大小写查重。
- 禁止空名、`.`、`..`、斜杠、控制字符和格式控制符；只允许删除没有物品和子目录的文件夹。
- 单个物品样本的完整序列化数据最多 8 KiB；拒绝直接嵌套本模组终端。
- 目录和物品写入方块实体 NBT，格式版本为 1。每次库存或目录变更调用 `setChanged()`。
- 拆除时清空库存并掉落普通物品，目录结构不保留；方块物品不会额外携带同一份库存。

这些是首版暂定值，不代表已经完成平衡性设计。目前未提供配置文件。

## 界面与同步

- 原生 `AbstractContainerScreen`，灰色像素边框和凹槽，保留原版按钮及背包槽位样式。
- 窗口按可用逻辑分辨率从 320 × 234 扩大到 440 × 340，每页 6–25 个条目。
- 当前目录的直接子文件夹排在物品前面，共同分页；点击文件夹卡片进入目录。
- 目录树支持滚动、展开 / 折叠，路径中的祖先目录可点击导航。
- 拖拽物品可投放到目录树、主区域文件夹卡片或路径中的目录。
- 背包槽位仅在客户端重新排布；菜单槽位 ID 和底层背包索引保持不变。
- 操作说明使用按钮悬停提示，成功操作保持安静，错误提示短暂显示。
- 支持新建 / 改名 / 删除空目录、按数量取出、拖拽移动、按钮选择目标目录和快捷存取。
- 左侧数量框对移动和取出生效；“全部”只填写所选条目的数量，不立即转移物品。
- 客户端发送请求，服务端验证打开的菜单、容器 ID、方块实体、距离、旁观者状态及库存版本。
- 变更请求使用 revision 防止依照过期库存操作；导航请求不要求相同版本。
- 每个菜单每游戏刻最多处理 10 个自定义请求。
- 多个打开的菜单检测库存 revision 变化后刷新；删除当前目录时退回主存储盘。
- 快照包含受限目录树、当前页的文件夹 ID 和物品；页面大小由客户端布局请求，服务端限制在 6–30。
- 网络协议版本为 2；库存存档版本仍为 1，保留原有目录与库存。
- 取出先填现有同类堆叠，再填 36 个主背包槽位；不触碰装备和副手槽。
- Shift 存入使用原版容器点击流程；鼠标携带物品存入也由服务端执行并同步。

## 代码边界

库存与转移逻辑位于 `storage/`，方块与持久化位于 `block/`，菜单负责校验，
网络层负责消息编码和分发，`client/` 负责展示和输入。
测试位于独立 `gametest` source set，仅加入 GameTestServer，不打进发布 JAR。
