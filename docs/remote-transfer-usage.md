# 终端发送与基站无线网络

更新日期：2026-10-03。

构建、**187 项 GameTest** 和新版真实客户端验收均已通过，见
[紧凑发送界面验收](verification/2026-10-03/remote-transfer-ui/README.md)。验证包含接收方分页与身份选择、
数量快捷、独立收件设置、中文常规及最小窗口、离线拒绝、返回终端后光标物品保留，以及同帧多份快照不丢发送反馈。
前版传输规则验收保留在 [2026-10-01 记录](verification/2026-10-01/remote-transfer/README.md)。

同一有效基站下的终端可以通过本地接入互传。不同基站下的终端需要两座基站都开启“加入网络”，
才可在同维度内通信。基站默认不加入无线网络，接收终端默认不开放收件；无需供电。

## 使用流程

1. 搭好基站，把终端用数据导线连到基站背面网络接口。源端和接收端都需要完整、可达的基站。
2. 在接收终端选择本地盘或 NAS 硬盘，进入准备收件的目录，点击顶部的“收件设置”。
   若已选中物品，顶部入口显示“发送…”，可从发送面板进入收件设置。
3. 可给终端命名并保存，将当前目录设为收件目录，再开启接收。设置页会显示已绑定的收件盘和目录。
   配置保存在终端，不随其他玩家浏览目录而变化；仅浏览另一个目录不会重新绑定收件位置。
4. 跨基站发送时，分别打开两个基站控制器，开启加入网络。首版只有同维度公共通信网络，没有频道、配对码或玩家白名单。
5. 在发送终端的普通目录中选中物品，打开发送面板，设置数量并从列表中点选接收终端。
6. 核对发送摘要中的物品、件数、接收端和收件位置，点击发送。面板会显示结果并更新剩余库存。
   搜索结果需要先定位到普通目录；程序文件不能发送。

开启接收表示允许可通信的终端向指定目录存入物品，不开放远端浏览或取物。
现场能使用终端的玩家可以修改接收配置；现场能使用控制器的玩家可以切换联网。

## 发送面板

选中物品后，点击终端顶部的“发送…”打开主界面，查看所选物品、当前可用数量、接收终端列表和发送摘要。
未选中物品时，顶部入口显示“收件设置”，直接进入设置页。所选条目不再出现在当前目录页、磁盘离线或菜单上下文变化时，
面板会停止允许发送；返回目录确认物品后重新打开。

数量可直接输入，也可使用 **1、16、64、最大** 快捷按钮。“最大”按当前可用库存计算，并受单次 64 件上限约束。
例如库存为 9 件时，最大可发送 9 件；库存为 200 件时，最大可发送 64 件。库存不足的固定数量快捷按钮会禁用，
手动输入的数量超过库存时也不能提交。
物品数量以最新收到的服务端库存为准，发送时服务端还会再次检查。

接收方列表每页显示 3 个终端，使用上一页、下一页查看其他候选项，最多列出 64 个已加载且可达的接收终端。
列表会自动刷新，也可手动刷新。点击某一行才会选中目标，打开面板不会自动选择第一项。
发送摘要和目标提示可用于核对终端名、坐标、本地或跨站关系以及收件盘和目录；长名称或路径可通过提示查看。

选择以终端身份和接收配置版本为准，翻页不会把选择改成同一行上的另一台终端。
目标离线、关闭接收或修改收件配置后，旧选择失效，需要重新确认目标；同名终端不会互相替代。
点击发送会立即提交当前摘要中的操作，没有额外确认对话框。等待发送结果时不能重复提交，
成功和失败都会给出反馈；失败提示说明需要重新选择目标、等待基站冷却或处理容量等问题。
自动刷新不会清除仍在显示的操作结果。

## 收件设置

“收件设置”独立于发送主界面，用于保存终端名称、绑定当前浏览的盘和目录，以及开启或关闭接收。
发送物品不要求源终端开启接收。接收终端只需配置一次，后续可直接作为列表中的目标使用。

修改收件位置时，先返回终端，选好盘和目录，再进入设置页执行绑定；设置页展示的已绑定位置才是实际投递目标。
绑定盘已拔出或目录失效时不会自动改投其他位置，仍可关闭接收。
从发送面板进入设置时，返回会先回到发送面板，再返回到终端目录；未选物品而直接进入设置时，返回会直接回到终端。
Escape 按同样的层级返回。
在这些界面之间切换会保留当前终端菜单和鼠标上携带的物品。

## 基础规则

| 情况 | 行为 |
| --- | --- |
| 两终端属于同一完整基站 | 可直接发送，不要求基站开启无线联网 |
| 两终端属于不同基站 | 两座基站都需加入网络；只允许同维度，基础版无无线距离限制 |
| 源或目标没有有效基站接入 | 拒绝发送；已有的独立本地 NAS 浏览仍按原规则工作 |
| 任一必要设备、导线或结构区域未加载 | 拒绝发送，不主动加载区块 |
| 接收已关闭、收件目录删除、收件盘拔出或进入保护 | 拒绝发送，不改投根目录或其他盘 |
| 容量、条目位置或源物品不足 | 整单拒绝，源与目标保持原样 |
| 同一共享 NAS 的同一个目录 | 拒绝重复发送，不复制物品 |
| 同一共享 NAS 的不同目录 | 在该盘内部移动，容量总量不变 |
| 断线、拆塔、同坐标更换终端或旧界面请求 | 每次执行重新检查；失效请求拒绝 |

一次发送 **1–64 件**同一条目的物品，数量按物品件数计算，不受原版单堆上限限制。
每座基站在成功参与一次收发后等待 **20 tick** 才能参与下一次，发送和接收共用额度；
同一基站内部发送只占一次额度。失败不占用额度，界面可在刷新后重试。没有排队、在途库存或自动发送。
这一限制是基础吞吐规则，不是升级模块；冷却属于当前加载期间的运行状态。

收件目录绑定终端的稳定身份、磁盘 ID 和目录 ID；目录改名不改变目标。
同一硬盘搬到另一台仍可达的 NAS 后可继续接收，换成另一块盘则不会自动重新绑定。
接收配置改变后，发送者必须刷新目标再发送，防止旧选择误投新目录。

## 与已有功能的关系

基站之间的无线连接只负责发送物品，不合并两地 NAS 列表、导线拓扑或生产机器网络。
同一线路仍最多一个基站接口、256 段导线。生产线路仍要求恰好一个终端，
因此在已有生产线上添加第二个终端会使生产网络不满足原有条件；可把接收终端放在独立基站线路。
多个终端访问同一 NAS 时库存始终只有一份。

跨维度、网络分组/白名单、远端浏览、云盘、拖放发送、批量条目、排队和结构升级不在本版范围内。

## 一致性与保存边界

服务端在单个请求中重新验证双方连接、接收配置、挂载身份和库存，预先准备双方的新状态，
再一起发布数量变化。验证失败不会先扣除源物品。菜单会话、库存版本和已发布条目检查阻止旧请求重复转移。
物品名称、耐久、附魔和其他 NBT 保留；正常保存仍沿用终端方块实体和磁盘 SavedData。

**目前没有跨文件崩溃事务保证。** 本地盘保存在区块 NBT，NAS 硬盘分别保存到独立文件；
进程强杀、断电或保存中断可能让两端恢复到不同保存时点。同一 tick 完成传输不能解决这个持久化边界。
本版没有以旧库存快照自动覆盖新数据的恢复日志，也不把正常保存/加载测试等同于强杀恢复验证。
要提供该保证，需要后续把相关库存操作纳入统一的事务日志与保存协议。

验证命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 build runGameTestServer --console=plain
```

自动验证包含库存原子提交及远程连接/配置规则，发布网络协议为 **12**，客户端和服务端需同步更新。
