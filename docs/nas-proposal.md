# NAS 与硬盘扩容提案

状态：独立分盘主体已在 0.2.0-dev 实现。本文保留设计讨论与后续扩展建议；实际功能、连接方式和限制以 [NAS 使用说明](nas-usage.md) 为准。

当前范围：四盘位 NAS、容量分级硬盘、终端分盘浏览与同存档搬运；物流暂不实现，已提供内部 StorageAccess 接口及模拟存取。

## 目标

让玩家通过制造和安装硬盘扩大存储容量，保留按目录、用途和项目管理物资的特色。
支持科技整合包的大宗材料，同时限制物品数据与目录索引的实际内存开销。

## 设备职责

| 部件 | 建议职责 |
| --- | --- |
| 现有存储终端 | 保留 4,096 件本地库存作为入门设备；连接 NAS 后可切换查看本地与 NAS，避免隐式搬迁原库存 |
| NAS 机箱 | 管理硬盘槽、在线状态和存储访问；首版可采用 4 槽单方块原型 |
| 硬盘 | 仅按存储容量等级区分规格，并具有唯一身份；名称和用途由玩家决定，物品说明独立显示容量规格 |
| 扩展盘柜 | 后续连接更多盘位，不必重新设计终端界面 |

首版连接方式建议先采用同维度相邻连接。多方块机架、线缆、远程访问和 FE 供电可在基础机制稳定后加入。
机箱外观、连接距离、槽位数和配方均为提议，尚未确定。

## 硬盘规格与命名（已确认）

- 模组提供的是不同存储容量等级的通用硬盘，不设置“矿物盘”“工程盘”等用途类型。
- 容量规格可以使用“64K 存储硬盘”“256K 存储硬盘”“1M 存储硬盘”等名称；具体等级数值仍待确定。
- 各容量等级适用相同的物品存储规则，沿用统一的数据安全限制，不根据物品类别限制用途。
- 每块盘允许玩家自定义名称并自行创建目录；“矿物盘”“工程盘”等仅为玩家命名的示例。
- 未命名时显示容量规格名称；同规格盘通过盘位等辅助信息区分。盘位标识不作为磁盘身份。
- 支持在终端对整块硬盘重命名；重命名不改变容量、库存、目录或稳定磁盘 ID。
- 容量规格与自定义名称分别保存和展示，即使玩家改名，也能在硬盘提示或管理界面查看实际规格。
- 后续物流规则由玩家另行配置，不根据盘名推断用途或自动限制可存物品。

## 磁盘使用方式

### A. 合并存储池（备选，不作为当前实施方向）

- 玩家看到一个 NAS 根目录，安装新盘后总容量增加，原有文件夹保持不变。
- 界面展示已用量、在线总容量、已装硬盘与各盘规格。
- 存储池负责库存；首版可以让硬盘仅承担容量配额，不宣称每块盘携带特定物品。
- 移除配额盘前检查移除后的容量；若不足以容纳现有库存则拒绝拔出，提示先扩容或取出物品。
- 这种配额盘拔下后不携带某一部分物品；NAS 搬家必须另外提供保留整个池身份的安全搬运机制。
- 如果希望每块盘都能携带真实数据，同时在界面合并显示，则要增加按盘分配、排空迁移与离线数据规则，不能直接沿用配额方案。

### B. 独立硬盘（当前主方案）

- 左侧每块已挂载硬盘显示为与“主存储盘”同级的磁盘节点，每块盘拥有自己的目录树和物品。
- 插盘增加可访问的磁盘，拔盘后该盘内容离线，再插入可以继续访问。
- 跨盘拖动是实际物品转移，需要验证目标容量并保证数量守恒。
- 拔出再插入、同一硬盘重复挂载和跨机箱搬运都需要身份及所有权校验。

独立硬盘的管理边界与对外物流接口可以分开设计；未来提供统一物流入口，不要求把各盘合并成共享容量池。

## 主体的最小实现闭环

建议首个可玩版本采用“四盘位单方块 NAS + 独立硬盘 + 相邻终端”，多方块机架留给后续迭代。
这是一组实现默认值，尚未确定最终外观和配方。

### NAS 机箱

- 右键打开盘位管理界面，显示 4 个硬盘槽、盘名、各盘已用量 / 容量和挂载状态。
- 槽位只接受本模组硬盘，硬盘不可堆叠。
- 支持安装硬盘和取出硬盘；先撤销挂载、失效旧访问会话，再把硬盘交还玩家。
- 玩家背包放不下时，取盘操作失败并保持盘位不变。
- 正常拆除机箱时掉落硬盘物品，避免把磁盘中的海量库存转换成地面掉落物；须验证只掉落一次。
- NAS 只管理盘位和挂载，磁盘库存不归属于机箱坐标；同一世界内换机箱后目录和物品保持不变。

### 硬盘物品和卷数据

- 硬盘规格只区分容量等级，服务器首次初始化硬盘时分配唯一磁盘 ID；用途不进入硬盘类型定义。
- 每块盘都有独立名称、根目录、库存、容量、版本号和保护状态。
- 硬盘物品携带轻量身份数据；完整库存按盘存放在世界数据中，避免背包网络包携带大量 NBT。
- 已有磁盘 ID 对应的数据缺失时进入错误状态，不把它重新初始化为空盘。
- 同一磁盘 ID 同时出现在两个挂载位置时，拒绝重复挂载；不能通过复制物品 NBT 得到第二份库存。
- 磁盘规格是容量依据，不能信任客户端传入的容量数字；调整规格与降容需另设明确策略。
- 硬盘可在同一个存档的机箱间搬运；复制硬盘物品到另一存档不能自动带走服务器端卷数据。

### 终端分盘浏览

- 保留当前终端的本地 4,096 件库存和“主存储盘”节点，各硬盘节点与它并列。
- 终端首版绑定同维度相邻的一台 NAS；存在多台候选时明确选择，不随机切换库存来源。
- 在本地存储和 NAS 的不同硬盘之间切换；每次显示当前盘的目录树、容量及库存。
- 当前右键取 1 个、Shift 存取、同盘目录拖动等操作继续使用，作用范围限定到当前选中的盘。
- 切盘时清空选中物品、拖动和目标选择状态，避免把旧盘的条目 ID 用在新盘上。
- 拔盘或 NAS 离线后显示不可用并拒绝旧请求，不悄悄切换到另一个盘继续存入。
- 首轮闭环可先通过背包在两盘之间搬物品；直接跨盘拖动需另做双盘事务与恢复测试，再加入。

## 代码拆分建议

以下名称是拟议职责，不代表已经创建对应 Java 类。

| 模块 | 职责 |
| --- | --- |
| `StorageVolume` / `StorageLimits` | 独立卷的库存、目录、动态上限和大数量计算；复用并保留当前 P0 校验 |
| `DiskItem` / `DiskTier` | 通用硬盘物品、容量等级和轻量身份信息；自定义名称独立于等级 |
| `DiskSavedData` | 按盘持久化、格式版本、保护数据和恢复记录 |
| `DiskMountService` | 挂载 / 卸载、同 ID 冲突检测、挂载代次和在线状态 |
| `NasBlockEntity` / `NasMenu` | 机箱盘位、玩家安装 / 取盘与掉落处理 |
| `StorageAccess` | 终端使用的统一存取入口；以后物流从同一入口接入 |
| 现有 `StorageMenu` / `StorageScreen` | 增加存储来源选择，使用服务端返回的容量和数量，而非固定常量 |

稳定定位使用磁盘 ID；执行操作时还需检查挂载代次与库存 revision。
两者职责不同：磁盘 ID 允许改名和搬运后继续识别，挂载代次用于拒绝上一次插盘会话留下的请求。
同一盘内的条目 ID 和目录 ID 必须与磁盘 ID 一起使用，不能在不同盘之间混用。

## 为物流扩展预留的边界

以下是接口和行为建议，尚未实现或确定具体界面。

当前只规划内部 `StorageAccess` 入口；首轮不注册物品物流 capability，不增加漏斗、管道、
输入 / 输出方块、缓冲槽或分类路由。外部适配留到后续独立开发。
该入口首先由终端实际使用，避免只留下一个没有真实调用路径的空接口。

入口应覆盖状态 / 容量查询、分页查询、指定目录的模拟和实际存取。
离线、保护、满盘和目标失效分别返回明确结果；模拟操作不修改库存、revision 或脏标记。

- 库存层提供按磁盘身份及文件夹 ID 执行的查询、模拟存取和实际存取接口；终端和物流共用这些规则。
- 对外通过 Forge `IItemHandler` 适配，不要求外部管道理解目录树。模拟调用不得改动库存或版本，实际操作只转移能接受的数量。
- 初版物流入口建议绑定玩家指定的一块盘及目录，例如玩家自行命名的“矿物盘 / 原矿”；显示名称可改，绑定使用稳定磁盘 ID 和目录 ID。
- 挂载关系还需有会话或代次校验，防止拔盘、换盘后，延迟请求作用到另一次挂载。
- 目标满盘、离线、目录被删除或进入保护状态时，直接存取接口返回未接收部分或空取出结果；不能静默切换到其他盘。
- 如果后续增加缓冲槽，应对外暴露稳定槽位，由 NAS 在每 tick 的有限工作量内搬运。目标失效时留在缓冲槽，不丢弃物品。
- 进阶路由可以按物品、标签和优先级选择多个明确授权的目标；满盘转投其他盘是可选规则，必须由玩家配置。
- 输出优先限定磁盘 / 目录范围，再增加过滤器和最低保留数量，避免自动化抽走工程预留物资。
- 初版不自动暴露所有盘和整个目录树为一组变化的物品槽，避免插拔盘或移动条目改变外部管道正在访问的槽位含义。

物流兼容主要取决于适配器是否遵守接口契约，独立分盘增加的是路由策略和状态变化处理。
更基础的难点是盘身份、同世界搬运、跨盘转移的数量守恒以及持久化恢复；仅给硬盘加 UUID 并不能解决这些问题。
世界数据方案默认支持同一世界内搬盘，跨存档携带不自动成立，需另设导入 / 导出格式。

## 容量与性能

容量级别可先用 64K、256K、1M、16M 做原型，再按整合包需求开放配置；具体数值和成本尚未定稿。
一百万个同种铁锭可以记录为“一个物品样本 + 数量”，而不是构造一百万个 ItemStack。
真正影响资源消耗的是不同物品数据、目录分配记录、索引和持久化规模。

当前代码需要同时处理：

- `StorageInventory` 的固定 4,096 件容量与 128 条目上限。
- 库存数量、合计、存档、网络快照与操作请求中的 `int`；NAS 计数建议使用有溢出检查的 `long`。
- 玩家背包转移仍按原版堆叠上限产生普通 ItemStack，不能把大整数直接强转为堆叠数量。
- `StorageScreen` 的 4 位数量框、容量常量，以及“全部”按钮的大数量行为。
- 同物品分到多个文件夹的重复样本开销，可将物品样本和目录分配记录分离。
- 条目、目录和物品数据需要独立的资源预算；不把“无限种类”作为承诺，也不盲目放大 8 KiB 单样本限制。
- 扩大规模后维护库存索引与缓存总量，避免每次操作扫描全部记录；继续只同步当前页和所需目录。
- 搜索应查询整个存储范围，不只过滤客户端当前页；是大型 NAS 投入日常使用前的重要配套。

## 持久化和安全边界

先抽出库存访问接口，使菜单可以访问本地库存或 NAS，而不是直接绑定终端方块实体。
NAS 的大体量库存建议保存在服务端世界数据中，硬盘 / 机箱物品只携带必要身份和展示信息，
避免把全量库存放入一个物品 NBT 后通过背包同步。

Forge 1.20.1 的 SavedData 可以承载世界数据，变更后需要调用 `setDirty()`。
它不自动提供磁盘去重、跨玩家背包与世界数据的原子事务、故障恢复或区块加载许可；这些需要项目自己实现。
独立分盘方案可按磁盘组织数据，避免每次修改都重写整个服务器的全部 NAS 库存。

必须明确验证：

- 同一身份只能在一个有效位置挂载；复制带 UUID 的物品不能复制库存或重复增加容量。
- 拔盘、机箱拆除、爆炸、区块卸载与服务器重启后的库存归属。
- 满容量、缩容和配置降低时不截断库存；应拒绝操作或进入明确的只取不存状态。
- NAS 区块未加载时终端显示离线，不因查询库存而无限加载区块。
- 两个终端同时访问同一硬盘时，共享该盘的服务端库存版本与容量检查；跨盘操作同时验证两盘及挂载关系。
- 旧版本 1 存档继续使用原有校验；新 NAS 格式单独版本化，迁移前保留原始备份。
- 数据缺失、未知版本或恢复失败时保留 P0 的锁定和备份原则，不创建空库存覆盖原数据。

## 建议实施顺序

1. 按独立分盘完善拔盘、跨机箱搬运和跨盘转移行为。
2. 抽离存储访问接口，增加动态容量与大数量计数；原终端回归测试继续通过。
3. 实现 NAS 方块、硬盘物品、盘位界面和本地连接。
4. 实现身份注册、持久化、拆装与异常恢复测试。
5. 验证主体闭环：插盘、两盘隔离、容量边界、同世界搬盘、重复挂载、旧请求、机箱拆除和重启恢复。
6. 后续补齐搜索和直接跨盘移动，再单独开展物流、盘柜和远程终端；物流开发从固定盘 / 目录的适配开始。
