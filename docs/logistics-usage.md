# 文件夹物流接口 · 0.3.0-dev

外部物流接口已实现，适用于 Forge 1.20.1。每个接口开放一个硬盘 / 文件夹范围，
由原版漏斗或其他模组管道、总线完成运输。内部无线发送与云存储仍处于规划阶段。

## 放置与连接

1. 合成“文件夹物流接口”，或使用 `/give @s itemexplorer:logistics_port`；创造模式中位于独立的“物品资源管理器”分页。
2. 拿着接口，潜行右键 NAS 或存储终端的一个表面。支持上、下和四个侧面。
3. 接口背面贴住宿主，外侧中央接头连接管道、漏斗或 AE2 总线。
4. 右键接口打开配置。新接口默认不开放库存，应用配置后才工作。

接口是独占相邻方块位置的薄面板，不能与其他模组管道共占一格。
面板为 6 × 6 模型单位，厚 1/16 格，含中央插口共凸出 2/16 格。
外侧相邻位置有设备时，中央细连接段才伸至格子边界；草、水、普通石块不会触发。
这段连接用于跨过接口自身占据的格子，因此接上管道时仍需保留长度；截面已缩至 1.5 × 1.5 模型单位。
接口只从外侧面提供物品 capability，背面及四周不提供；无方向的内部查询也可取得同一访问范围。
外观上将非可替换且具有方块实体的相邻方块视为设备，不表示已经确认第三方物流支持连接。
旧存档中误伸出的连接段会在加载后自动重算，无需拆除接口。

贴 NAS 时可选择该 NAS 在线硬盘；贴终端时还可选择终端本地盘，以及终端背后 NAS 的在线硬盘。
接口只识别本模组 NAS 和终端，不代理普通箱子或其他机器。宿主被拆除时，接口按普通方块规则掉落，
接口自身没有缓冲库存；拆除接口不会掉落或搬迁目标盘物品。重新放置后需要配置。

配方三行依次为 ` I `、`RHC`、` I `，产出一个接口。
I = 铁锭，R = 红石粉，H = 漏斗，C = 红石比较器；空格表示空槽。

## 配置

| 控件 | 行为 |
| --- | --- |
| 顶部硬盘按钮 | 依次选择可访问的盘，属于配置预览，不立即切换运行目标 |
| 文件夹列表 | 选择目标目录；滚轮或右侧箭头浏览，悬停查看完整路径 |
| 允许存入 | 是否接受外部输入 |
| 允许取出 | 是否允许外部抽取 |
| 包含子文件夹 | 查询和取出是否递归覆盖目标下的子目录；输入始终进入选中的目录 |
| 应用配置 | 将当前选择及开关保存到接口，替换旧配置 |
| 断开绑定 | 立即停止该接口访问，盘内物品和目录保持不变 |

选择一块盘后，默认目标是根目录。根目录不自动包含子文件夹，需要明确开启对应选项。
存入与取出都关闭时，接口停用运输，但仍可查询其开放范围；存取方向不等于物品信息的保密权限。
配置属于接口，不随终端正在浏览的目录变化。盘或目录改名不影响绑定。

例如，将接口绑定“公共材料 / 铁锭”，管道即可直接归档和取用该目录的物品，
同一盘的“铁路工程”目录不会因此开放。物品筛选可使用现有管道或总线的过滤器。
当前没有接口自身的物品白名单、最低保留量、优先级或自动转投规则。

## 状态与异常

- 灯灭：未配置、已停用或硬盘离线。
- 绿灯：目标可用。满盘时仍保持在线，界面提示容量已满；允许取出时可继续输出。
- 青灯：近期由该接口完成过实际物品转移；模拟和查询不触发。
- 红灯：配置 / 库存受保护、硬盘挂载异常，或目标目录不存在。

拔盘、目标删除、区块卸载、数据保护等情况会拒绝对应存取，不自动切到其他盘或根目录。
同一块盘重新挂载后，新访问可继续按原绑定工作，旧挂载的接口引用不能继续存取。
满盘只接受能放下的数量，其余按 Forge 接口约定返回给运输方。
禁止嵌套存储设备、物品 NBT 大小等限制沿用库存层规则。

配置写入接口方块实体 NBT，不保存第二份盘库存。未知或损坏的配置原样保留并禁用访问，
服务端尝试归档到世界的 `itemexplorer-recovery/`；拆除前会重试归档。
更改配置需要当前菜单会话、配置版本和挂载上下文全部有效，旧界面请求不能重新绑定已换盘的接口。

## 兼容接口与开发验证

接口暴露标准 `IItemHandler`。槽位 0 是存入入口，不虚构缓冲物品；其余槽位只展示开放范围内的真实库存。
有效条目的槽位不因前面的条目被取空而前移。每次调用重新验证在线挂载，配置或挂载失效后旧引用拒绝操作。
查询可以显示超过原版堆叠上限的库存数量，单次抽取返回合法大小的 ItemStack。

基础回归使用 `dev.ps1 build runGameTestServer --console=plain`。
可选的真实模组测试使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\dev.ps1 runGameTestServer --init-script scripts/compat-test.init.gradle --console=plain
```

该配置仅在开发验证时载入 AE2 15.4.11、MEK 10.4.16.80、GuideME 20.1.15，
使用独立的 `work/compat-gametest/` 世界，测试源码位于 `src/compatTest/`。
发布 JAR 不打包测试类或上述模组，也不将它们设为强制依赖。
实际通过的验证项目与尚未完成的目视验收见 [开发验证记录](setup-verification.md)。

## 外观资源与复现

接口采用灰色金属薄面板、方形插口、文件夹标识和状态灯；装饰和灯色直接使用表面纹理，避免重叠贴片闪烁。
四档硬盘改用共享金属外壳模型、32 × 32 专用容量铭牌贴图和金色触点，保留绿、青、紫、橙色标。
这些是 Minecraft 原生模型与像素纹理；概念图不直接作为游戏贴图。

运行 `node scripts/generate-logistics-assets.mjs` 可复现本次接口及硬盘资源。
运行 `node scripts/check-logistics-models.mjs` 检查硬盘、接口物品及接口状态组合的共面 / 近共面重叠。
独立客户端检查可用 `dev.ps1 runClient --init-script scripts/logistics-review.init.gradle`；
在该测试客户端的独立测试世界中执行 `/itemexplorer-review` 可生成演示设备。
此命令会替换测试世界中 x=-4..5、z=-5..4、y=81..87 的场景，只用于专用测试世界。

网络协议更新为 5，客户端与服务端需要同时更新至 0.3.0-dev。
